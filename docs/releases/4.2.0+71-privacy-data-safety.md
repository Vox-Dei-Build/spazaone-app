# SpazaOne 4.2.0+71 privacy and store data declarations

This is the implementation-backed worksheet for App Store Connect and Google
Play Console. It is not a record of submitted answers: no store field has been
changed or saved.

## Public URLs

- Privacy policy: `https://spazaone.com/privacy-policy`
- Support: `https://spazaone.com/support`

The website source contains all three routes. They must be deployed and checked
publicly before the URLs are saved in either store console.

## Important behavior corrected in this release

- Product analytics and crash reporting remain off until the merchant makes a
  choice.
- Consent copy no longer calls account-linked analytics “anonymous” or claims
  crash reports contain no personal data.
- Session replay is disabled. PostHog Flutter 4.11 cannot honour an independent
  replay choice at runtime; leaving it enabled would make the old toggle
  misleading.
- PostHog exception events no longer include raw exception messages.
- The in-app privacy screen links to the public SpazaOne privacy policy.

## Apple App Privacy recommendation

Answer **Yes** to data collection. The app does not display third-party ads and
the audited binary does not link AdSupport or AppTrackingTransparency, so IDFA
is unavailable. Treat “data used to track you” as **pending**, not a source-code
answer: Firebase Analytics events are mirrored into GA4/Google Ads, and the
property configuration determines whether app data is linked with third-party
data for advertising measurement. Answer **No** only after confirming that no
such linkage occurs. If it does occur, stop, answer **Yes**, and review ATT
requirements before release.

Unless noted otherwise, mark the types below as **linked to the user**. The app
uses the Firebase account ID in PostHog and Crashlytics, and core business data
is stored below that account.

| Name | App Functionality | Required during profile completion | Merchant profile |
| Email Address | App Functionality | Optional | Email auth/payment email paths |

| Payment Info | App Functionality | Optional | Bank-account details for payouts. Do **not** include Paystack card number/CVV: those are entered on Paystack’s hosted page and SpazaOne never receives them. |

## Google Play Data safety recommendation

### Top-level answers

- Does the app collect or share required user data types? **Yes**
- Is all collected data encrypted in transit? **Yes** — app-controlled network
  traffic uses HTTPS/TLS and Firebase documents encryption in transit.
- Can users request deletion? **Yes**
- Account deletion URL: `https://spazaone.com/delete-account`
- Is data shared? **No**, provided Firebase/Google Cloud, PostHog, Twilio,
  Botpress, Paystack and Vercel are configured contractually as service
  providers processing on SpazaOne’s instructions. Google’s form excludes
  service-provider transfers from “sharing”. If any provider independently
  uses the data for its own advertising profile or other purpose, change this
  answer before submission.

## Security, deletion and retention notes for reviewer responses

- Authentication and service calls use Firebase Auth/App Check and HTTPS/TLS.
- The app supports in-app deletion at Settings → Delete Account and an outside
  request route at `https://spazaone.com/delete-account`.
- The deletion Cloud Function removes the Firebase Auth user, the user document
  and recursive subcollections, related promotions, payout requests, payment
  references, notifications, message templates and known Storage media.
- Provider backups/logs and legally required payment/accounting records can
  outlive the live account. The public policy discloses this.
- Firebase says Authentication data can take up to 180 days to leave live and
  backup systems after deletion; Crashlytics retains crash data for 90 days.

## Final checks before saving either console

1. Deploy the three public routes and verify they are non-editable, publicly
   accessible, HTTPS, and not geofenced.
2. Confirm the legal/developer name displayed in each store still has a clear
   relationship to “SpazaOne (previously Pasella)” in the public policy.
3. Confirm each named processor is operating as SpazaOne’s service provider.
4. Confirm the Firebase/GA4 property is not linking iOS user/device data with
   third-party data for advertising measurement. If it is, stop and review
   Apple tracking/ATT before submission.
5. Export the current Google Play Data safety CSV before editing, map these
   answers into a draft, and compare the preview before submitting.
6. Save store privacy answers only after explicit approval.
