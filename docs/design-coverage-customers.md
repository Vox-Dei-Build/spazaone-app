The implemented direction is **Clean and approachable**: shared forest headings, muted secondary text, white rounded surfaces, medium-weight amounts, fixed typography and spacing with Flutter accessibility scaling. This inventory covers presentation under `lib/pages/contact`, `lib/pages/ledger`, `lib/pages/transactions` and `lib/pages/reports`.

## Safe preview module

`tool/customer_design_previews.dart` exports `Map<String, WidgetBuilder> customerDesignPreviews()` with six screen builders: **Customers**, **Customer account**, **Customer messages**, **Record customer payment**, **Repayment plan**, and **Customer insights**. Every builder supplies its own Scaffold. Navigation/back actions stay local. The module uses production TransactionTile, CustomerBalanceCard, CustomerAccountActions, TransactionCard/TransactionDate, MessagesListView, CustomerPaymentFields, RepaymentPlanSheet and CustomerReportContent.

Fixtures contain synthetic customer names, numbers and transactions; no Firebase initialization, live data read, message send or write occurs. Preview recording produces a local notice; repayment-plan submission only returns a draft from the route. Actual account eligibility and network-dependent flows are covered by the existing injected-gateway tests, not by fabricated live outcomes in the gallery.
